# Cats Bot 0.2.0 — Standard Preview

First GitHub Standard Preview of the resident desktop Bot. The Bot keeps its
Runtime alive independently of note windows and includes first-run setup, settings,
multiple conversations, a floating cat, scheduled work, heartbeat and optional
Telegram integration. Codex and Claude Code execute through the pinned Runtime;
provider approvals and questions can be answered from the Bot. Browser/computer
tools still require the provider's plugins, connected browser/helper and OS access.

## Signing and updates

This release uses the standard signing profile. macOS is prepared to use the same
Developer ID Application certificate and notarization API key as Cats Desktop,
shared only with the two repositories through organization secrets. The signed
macOS build must pass signature, Gatekeeper and stapled-ticket validation before
publication. Windows has no configured Authenticode certificate and is explicitly
unsigned. Linux DEBs are unsigned and require OS package-manager authorization.
The platform receipts record the trust actually produced by the build.

Use **Check for Updates** in the tray/floating cat menu or Settings → App. Checking,
downloading and installing are separate user actions. There are no automatic
background checks or downloads. Installed Windows NSIS, signed macOS and Linux
DEB distributions support their platform update path; portable builds open the
release page for manual replacement. Quit every other Bot using the installation
before installing an update. The active Bot stops its Runtime before replacement.

## Compatibility, upgrade and recovery

This is the first published version. Existing development and CI packages marked
0.1.0 need one manual installation; they do not become updater-enabled packages.
An existing unsigned macOS installation also needs one manual signed installation.
Provider CLIs must already be installed and authenticated for the operating-system
account running the Bot. They and their browser/desktop helper installations are
not included in these installers.

Before upgrading a development installation, quit its Bots and back up the entire
Bot data directory (`~/.cats/bots`, or the configured `CATS_BOTS_HOME`). The 0.2
boundary includes profile schema 2 and explicit provider-policy data. Existing
schema-1 profiles are validated under the Bot's instance lock, retain their
legacy permissions, and receive a byte-preserving `profile.json.v1.bak` before
atomic replacement. Read-only inspection does not migrate a profile. Unknown
schemas, invalid permission boundaries or a conflicting backup stop loading
without overwriting the original data or backup.

If migration fails, keep the reported files and backup, quit the Bot, and correct
the reported cause before retrying. To return to an older development build,
restore the complete pre-upgrade data backup while all Bots are stopped; do not
point it at a schema-2 profile. An uncertain installer handoff retains its update
gate until the new version starts or the user confirms the installer has finished.

## Reproducible inputs and validation boundary

- Bot version: `0.2.0`; the workflow records the exact release commit in the
  release body, packaged descriptors and source manifest, and binds tag `v0.2.0`
  to that commit.
- Runtime version: `0.6.2` from commit
  `e38e56bfd54fe783df22a5e0d914b14d186ee6bf` in `cats-inc/cats-runtime`.
- Vendored Runtime: `vendor/cats-runtime-0.6.2-e38e56bf.tgz`.
- Runtime SHA-256:
  `84efc380cc3289584d1f27f8a16cc09b032d572284257ecad7e6becdb1df169d`.
- Dependency versions and tarball SHA-512 are fixed by `package-lock.json`.
  Release asset digests are generated as `SHA256SUMS` and checked against GitHub
  uploads before the draft becomes public.

Publication requires the three-platform test/build/package matrix, complete-source
and updater-metadata checks, and the applicable signing checks. The shared
packager verifies both macOS architecture slices in candidate CI and release
builds. Hosted Actions
results and assets are the release evidence. A credential probe is not full app
notarization; package tests are not an installed update from one public version
to another. There is no earlier public Bots release for that upgrade comparison.
