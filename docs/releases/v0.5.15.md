# Cats Bot 0.5.15 — Standard Preview

This compatible 0.5 patch makes Kimi Code the sixth agent CLI. It lets the owner allow a conversation's
computer use, commands or file changes once, with Stop always in reach. Direct messages can be cleared, and
the floating cat gets a quick menu. Bot keeps profile schema 2, version-1 conversations and JSONL journals;
the new fields are optional and older builds ignore them.

## Changes and exact inputs

- **Source selection:** cats-runtime@7c7e9e102933fab7326bc278e7279b07d287444e; main@7c7e9e102933fab7326bc278e7279b07d287444e.
- **Kimi Code, the sixth CLI (#190, #192, ADR-025).**
  - Kimi runs only on Runtime's hosted `kimi acp` target, never in print mode. Print mode would run an
    installed computer-use plugin (`kimi-cu-win`) without asking.
  - In Default mode Kimi asks before each computer-use, shell and file call, through the note's approval
    cards. Its computer use comes from the plugin the owner installs in Kimi with `/plugins`; Cats never
    installs or configures it.
  - Kimi runs only with full machine access, so creating a Kimi bot with a read-only filespace or an
    allowlist is refused.
  - A Kimi bot's policy carries an optional `providerPolicyAuto` marker. Leaving Kimi drops only the policy
    Kimi brought, never one the owner set.
  - Setup, sign-in and removal helpers come from Cats Desktop.
- **Allow once, Stop always (#193, ADR-028, Runtime ADR-055).**
  - A card that Runtime tags with a grant category (`computer_use`, `command`, `file`) offers "Allow for
    this conversation" and "Allow for 30 minutes".
  - Only messages the owner sends from a note or the local `cats-bot say` use grants. Telegram,
    heartbeats, schedules, recovery turns and answers to the bot's own questions never do. A contact note
    can never grant.
  - A request answered from a grant never waits for the owner and never shows as a card.
  - While grants are in force, the note shows them with Stop, and the tray's first item and the global
    `Ctrl+Alt+Shift+S` hotkey (registered only then; Control+Option+Shift+S on macOS) stop every bot. `cats-bot grants [--stop [--all]]`
    does the same from the CLI.
  - Stop cancels the running turn and revokes in Runtime. Unless Runtime confirms, the note and the CLI
    say so; a failed Stop from the tray or the hotkey is only logged. A grant of computer use is as broad
    as the owner at the keyboard; the card says so.
- **Notes and Settings.**
  - A note made without a name takes its first message and is then named from its first exchange, as
    Cats Desktop does (#191).
  - Settings › Conversations gives every row the same controls. The direct message can be cleared: its
    work is cancelled, its transcript and journal text go, and its Runtime sessions are deleted (#194,
    ADR-026).
  - The note's model line follows Cats Desktop's audience chip, and the bot's folder is its Filespace
    (#188). A waiting bubble shows until the reply starts (#189).
- **The floating cat (#195, ADR-027).** A single click opens a quick menu with the direct message and the
  four latest notes; a double click opens the direct message.

## Compatibility, backup and recovery

No data migration or schema change is introduced. New optional fields, which older builds ignore:
- `providerPolicyAuto` in a profile;
- `cleared` and `retiredSessionIds` in a conversation;
- `titleSource` and `titleAttempts` in a conversation;
- a quick-menu preference.

After a downgrade, work from before a clear can show again, and drafted note names read as titles.

A bot whose CLI is Kimi needs this version: 0.5.14 and earlier do not know Kimi, and its behavior there is
not verified. Switch such a bot to another CLI before going back.

Before installation, stop Cats Bot and processes using its roots. Back up `~/.catsbot` or configured
CATS_BOT_HOME/overrides, Electron preferences and `.cats-attachments/` in each Bot working directory. On
installation or startup failure, preserve those roots and reinstall 0.5.15 or return to 0.5.14 with
processes stopped. Restore backups only while writers are stopped; rollback does not recreate data
explicitly purged by the owner.

## Standard distribution and trust

Windows x64/arm64 receive NSIS installers and portable EXEs; macOS receives a universal x64/arm64 DMG and
updater ZIP; Linux amd64/arm64 receive DEBs. Standard expected trust is macOS **signed + notarized**,
Windows **unsigned: no certificate**, Linux **n/a**. Native checks and per-platform receipts establish
actual trust. Same-team signed macOS, Windows NSIS and Linux DEB retain their update paths; portable and
unsigned macOS installations require manual replacement.

Publication results: the `v0.5.15` GitHub Standard Preview, platform/source receipts, checksums,
provenance and Actions run.
