# Cats Bot 0.5.16 — Standard Preview

This 0.5 patch makes a cat bot's settings and the setup wizard the same three pages, and asks two questions about
permissions in place of the tool allowlist. No check stops the wizard, and an owner's message replaces a session
that never started. The floating Cat can stack and spread its notes, and its quick menu tags conversations
waiting for the owner. Runtime moves to package version 0.7.0. Bot keeps profile schema 2, version-1
conversations and JSONL journals. A profile that still has a tool allowlist is upgraded once, with a copy kept.

## Changes and exact inputs

- **Source selection:** cats-runtime@a1f898a2acf04d925171ae12d88b18cbe20538d7; main@a1f898a2acf04d925171ae12d88b18cbe20538d7.
- **A cat bot's settings are the wizard's pages (#201, ADR-030).**
  - The Cat bot tab becomes Name and look, Provider and model, and Permissions. One save bar says what a save
    will do before it is pressed. The session check moves to Details.
  - Permissions asks whether the cat bot asks before it acts and what it can reach. It offers each provider only
    what Runtime admits, an untouched page sends nothing, and each provider's default stays its default.
  - The tool allowlist is removed; see the one-time profile upgrade below.
  - On Provider and model and on Cats Bot Settings' Agent CLIs tab, each CLI row has one action (Install, Set up
    or Update). The action asks in a box under the row, naming what will run. "Set up all N" and "Update all N"
    replace the ticks, a run's report stays on its row, and the log opens when asked for.
- **The setup wizard is those pages, and no check stops it (#207, #209, ADR-032).**
  - The wizard's pages are Name and look, Provider and model, and Permissions, with the settings page's own rows
    on page 2. A ready row offers no Update, because the wizard only installs. A row Cats Bot cannot find yet
    offers "Restart Cats Bot" and keeps what was typed.
  - Nothing a check finds disables Next or Create, and neither creation entry point refuses. Create waits only
    while a check or a step runs. It then looks, read-only, where the chosen CLI is, so the new core inherits its
    folder on PATH.
  - Page 3 says what the new cat bot may do, with its provider's default unchanged.
  - When an owner's message fails and the provider's command is not on the PATH the core gives the Runtime, the
    note says "{provider} is not on this computer, so this message got no reply." and offers "Open Provider and
    model". This only words the failure. #209 removed the turn guard, the Runtime restart and the copy of the
    Runtime's command lookup that #207 had added, so whether a CLI launches stays the Runtime's call. The check is
    PATH only: a CLI the Runtime finds outside PATH can be named missing when a message fails for another reason.
- **A session that never started no longer blocks a conversation (#208, SPEC-001 FR-11).** A first turn that
  reached its CLI but failed to start, such as a failed sign-in, used to leave a Runtime session with no native ID.
  Every later message then failed with "No provider session ID to resume". The owner's next message now replaces
  such a session when nothing in it can be resumed: a Runtime-origin CLI record with no native ID on either side,
  no completed messages, no native history and no run going on. It replaces at most once per message, and the
  unanswered prompt reaches the new session through the handoff. Reconcile, heartbeats, schedules and events keep
  the mapping as before.
- **Cat bots list and Boss Cat (#204, ADR-031).**
  - Every row shares one grid: Auto-start, Start or Stop, Settings and Archive sit in the same columns, and
    nothing wraps or scrolls sideways at 600 px.
  - A running cat bot's row opens its own settings window, and the order is changed in its own mode.
  - The Boss Cat group holds the holder, the two limits in plain words and "What the Boss Cat can see". A limit
    out of range becomes the nearest one the hub accepts.
  - General is grouped, and the data folder joins the reset on Data, which lists what it erases and keeps.
- **The floating Cat (#199, #202, SPEC-002 FR-7a and FR-7b).**
  - Its right-click menu stacks that Cat's open notes beside it with every title bar showing, or spreads them
    over its display. Undo restores the last arrangement until one of those notes is moved, resized, maximized,
    minimized or attached. Desktop and wallpaper notes stay where the owner put them. Notes are raised without
    activation, so nothing is marked read.
  - The menu is regrouped. Requests waiting for the owner sit under the status, and the Cat's windows have their
    own group. "Hide this cat" replaces the "Show floating cat" checkbox, which was always ticked there.
  - The quick menu tags a conversation where something waits for the owner with "Needs you". Waiting notes come
    right after the direct message. Linux's native menu adds the tag to the title.

## Compatibility, backup and recovery

- **One-time profile upgrade (ADR-030).** A profile with `permissionMode: 'whitelist'` or `allowedTools` is
  upgraded once when its core starts.
  - In allowlist mode, Claude Code and Codex with a writable filespace move to Ask me first, an explicit
    full-access policy that asks before each action. A read-only filespace stays read-only, and other CLIs keep
    their own default. The list no longer decides which tools run: the cat bot follows the choice it moved to,
    and only Claude Code and Codex with a writable filespace ask before each action.
  - A list kept beside another mode is dropped, and nothing else changes.
  - A profile whose permissions are malformed is not changed: the cat bot reports a corrupt profile, the
    original stays and no copy is made.
  - The original is copied first to `profile.json.allowlist.bak` beside it (`profile.json.v1.bak` for a
    schema-1 profile). If an older Bot writes a list again, that version is kept as
    `profile.json.allowlist.<milliseconds>.bak` and upgraded again.
  - The profile is then replaced atomically. Leaving allowlist mode raises `configRevision`, so sessions made
    with the list are replaced with a handoff. An upgrade stopped after its copy finishes on the next start.
  - `tests/core/profile.test.ts` covers Claude Code, Codex and Grok, writable and read-only filespaces, a list
    beside another mode, a schema-1 profile, the copies, a list written again, malformed profiles and an
    upgrade stopped after its copy.
  - An older Bot reads an upgraded profile, but going back does not restore the list. To recover it, restore
    that copy with Cats Bot stopped.
- **Narrowed contract.** `cats-bot init --permission-mode` accepts `default` or `skip`; `whitelist` now exits
  with code 2. Creating or updating a profile refuses `permissionMode: 'whitelist'`, and an update through the
  host API refuses `allowedTools`. Runtime's own allowlist is untouched. Cats' compatibility policy places
  rejecting previously supported configuration at the next 0.x minor; the owner selected 0.5.16 for this
  release.
- **New optional fields**, which older builds ignore:
  - `fix` on a transcript entry; an older note shows the entry's English text;
  - `awaitingOwnerConversations` in a core's status. With a core from before it, the quick menu still tags
    provider requests and desktop-control grant requests, but not questions or approvals the bot asked.
- **Runtime 0.7.0.** No Runtime data migration is required. Stored sessions, catalogs, saved selections and
  configuration files load unchanged. Close, reset and delete can take up to 6 seconds while a provider process
  stops. Bot closes a session before deleting it. A delete that Runtime refuses is logged, and for a cleared
  direct message the session is tried again on its next clear.

Before installation, stop Cats Bot and processes using its roots. Back up `~/.catsbot` or configured
CATS_BOT_HOME/overrides, Electron preferences and `.cats-attachments/` in each Bot working directory. On
installation or startup failure, preserve those roots and reinstall 0.5.16, or return to 0.5.15 with processes
stopped. Restore backups only while writers are stopped; rollback does not recreate data explicitly purged by the
owner.

## Standard distribution and trust

Windows x64/arm64 receive NSIS installers and portable EXEs; macOS receives a universal x64/arm64 DMG and
updater ZIP; Linux amd64/arm64 receive DEBs. Standard expected trust is macOS **signed + notarized**,
Windows **unsigned: no certificate**, Linux **n/a**. Native checks and per-platform receipts establish
actual trust. Same-team signed macOS, Windows NSIS and Linux DEB retain their update paths; portable and
unsigned macOS installations require manual replacement.

Publication results: the `v0.5.16` GitHub Standard Preview, platform/source receipts, checksums,
provenance and Actions run.
