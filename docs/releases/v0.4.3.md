# Cats Bot 0.4.3 — Standard Preview

Bots can be told which language to reply in, the same way Cats Desktop's
assistants can. The setting is shared by every bot, and each bot can choose its
own. This release also bounds message retries, makes the Linux avatar
interactive again, fixes Linux taskbar icons and finishes macOS setup when Codex
is already installed. It is a patch: the new settings are optional fields, and
an existing installation keeps its sessions.

## What changed

- **Reply language** (#88, SPEC-008 FR-28).
  - **Cats Bot Settings → General → Reply language** offers Cats Desktop's
    choices in the same order:
    - **Same as display language (<language>)** comes first and names the
      display language in use, so a System display language shows what it
      resolved to.
    - English, Traditional Chinese, Simplified Chinese, Japanese, Korean,
      French, German, Spanish, Brazilian Portuguese, Italian, Dutch, Polish,
      Turkish, Indonesian, Vietnamese, Thai, Hindi and Arabic follow.
    - **Unspecified** comes last and is the default.
  - Each bot's **Bot** tab has its own **Reply language**:
    - **Follow Cats Bot Settings (<language>)**, the default, names what the
      shared setting resolves to.
    - The same choices follow.
  - The bot is told the language in its session instructions, worded as Desktop
    words it. A request in the conversation still takes priority.
  - When the language a bot is told changes, each of its conversations continues
    in a new session with a summary of what was said. The conversation says the
    reply language changed. A change that leaves the language as it was keeps the
    sessions.
- **Owner messages stop retrying** (#87).
  - Only a recognized busy session is retried, at most eight times for an owner
    message. Other conflicts keep their reason.
  - Deferred work stays cancellable, and finished work is not revived by an
    older snapshot.
  - Send and Cancel no longer flip back and forth while a message waits, and the
    controls return to idle when a completion notice is missed.
- **Linux avatar input** (#87, ADR-012).
  - Cats Bot runs on X11/XWayland when `DISPLAY` is available. The packaged
    launcher selects it, and a direct launch on an automatically chosen Wayland
    backend relaunches once.
  - The avatar can be dragged and clicked again. Input outside the cat, its
    bubble and its indicators passes through.
  - An explicit native Wayland backend is still honored, with the positioning
    limits ADR-012 describes.
- **Linux taskbar icons** (#83). The DEB installs icons at 16 to 512 pixels,
  and the desktop entry's name matches its window class, so taskbars that use
  the standard icon theme show the Cats Bot icon instead of a generic one.
- **macOS setup with Codex already installed** (#82). The npm-folder check no
  longer aborts under the system Bash 3.2, which had stopped first-run setup with
  "The provider helper returned an unreadable result". The provider list says
  "Claude", as Desktop does.
- **macOS menu-bar icon** (#86). It uses Desktop's 20pt canvas, with 20px and
  40px Retina images. Windows and Linux icons are unchanged.
- **Development tools** (#86). Cats Bot has its own graceful macOS CDP restart
  (port 9223), file-page renderer inspection and isolated source candidates. The
  development mechanisms it shares with Desktop are source-vendored with pinned
  commits and hashes. None of this changes the installed app's behavior.

## Compatibility, upgrade and recovery

- **A patch.** The new fields are optional, and each is read with a default when
  it is absent:
  - `hub-state.json` gains `replyLanguage`, which defaults to `unspecified`.
  - Each `profile.json` gains `replyLanguage` (default `hub`) and `hubLanguage`
    (the hub's last report, `null` until it reports).
  - Nothing else changes: no registry field, CLI command or schema number. Bot
    data, ids and the Boss Cat assignment are kept as they are.
- **No session resets on upgrade.** The shared setting starts as Unspecified,
  so bots are told what they were told before, and their sessions are kept.
- **Host contract.** The hub sends each core a new host-only `setHubLanguage`
  command. A core that refuses it still opens.
- **From 0.3.x or 0.2.x.** Follow the 0.4.0 release notes; 0.4.1 to 0.4.3 change
  nothing there.
- **Rollback to 0.4.2.**
  - 0.4.2 reads the same files and ignores the new fields, so bots are told no
    reply language.
  - When 0.4.2 saves a bot's profile, it drops that bot's own choice and the
    hub's last report. After a later return to 0.4.3, that bot follows Cats Bot
    Settings again until it is set again, and the hub reports when the bot opens.
  - 0.4.2 also returns to unbounded busy retries, the non-interactive Linux
    avatar and the single-size Linux icon.

    rerun the tests.
