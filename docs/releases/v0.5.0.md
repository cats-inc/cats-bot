# Cats Bot 0.5.0 — Standard Preview

This release replaces the first-run page with a three-page setup wizard. In the wizard, nothing on
the computer is checked until you ask, and no script that changes it runs until you tick it. It
starts the 0.5 line because `cats-bot init`, the app's `--name` option, `updateProfile` and the Boss
Cat tool now refuse names and personas they used to accept. Stored data keeps its format.

The maintainer chose to publish this preview without clean-machine acceptance. So far the wizard
has run only in a hidden window on Windows. It has not installed anything on a real machine, and it
has not run on real macOS or Linux desktops. See the acceptance boundary below before relying on it.

## Changes

- **A setup wizard for creating a cat bot** (#117, #118; ADR-015, SPEC-010). The first run, New
  cat bot and a Boss Cat's request for a provider this computer lacks now share one resizable
  window, with a minimum size of 800×600. A Boss Cat's request for a provider already on PATH still
  creates the bot directly.
  - **Who it is:** name, look, provider and an optional personality. This page starts no process
    and scans no PATH. No provider is preselected, unless a Boss Cat's request names one or the
    wizard restarted with your input. Five personality presets replace the box's content, and
    Ctrl+Z restores it.
  - **This computer:** read-only checks for the chosen provider run only after "Check this
    computer". Every script that changes something has a tick box, unticked by default. Its
    details show what the helper reports it would do, the command that really runs, the start of
    the script's SHA-256 and source commit, and a command for doing it by hand. "Apply" runs ticked
    rows one at a time from the top, with a fresh check after each. "Try again" appears only for a
    row you already ran.
  - **Sign-in and start:** "Open terminal and run" starts a new terminal with a fixed command per
    provider. No text from the page or a model reaches it, and no credential file is read. On a
    first run of an installed copy, starting Cats Bot at sign-in is a checkbox, ticked by default.
    Unticked leaves no new login item, and an existing one stays as it is.
  - **The log:** a read-only text area across the window's foot records each run's time, kind,
    full command and reported results. Any script run opens it. It closes after a success and stays
    open after a failure, including a check that fails or a terminal that cannot open. Once you
    toggle it, it stays as you set it, except that a failure opens it. The hub's diagnostics record
    each finished helper run in fixed words only.
  - **PowerShell scripts on Windows** is now optional and listed last. It no longer blocks Codex or
    finishing, and sign-in on Windows opens in Command Prompt whatever you chose.
- **One rule for a bot's name and persona** (#116). A name is one line of 1 to 40 UTF-16 units with
  at least one visible character, and its box stops at 40. A persona is at most 4,000 units and may
  use line feeds and tabs. Both refuse control characters, format characters such as bidirectional
  and tag characters, and every other character Unicode marks as default-ignorable.
  - **What stays:** an emoji or symbol keeps U+FE0E or U+FE0F right after it. A persona also keeps
    the zero-width joiner and non-joiner that emoji and some scripts need, right after a letter,
    mark, emoji or symbol.
  - **What this refuses that you might use:** a name cannot hold an emoji built with a joiner, or a
    spelling that needs one in Persian, Sinhala and other scripts. Neither a name nor a persona can
    hold the England, Scotland and Wales flags, which are built from tag characters, or text using
    ideographic or Mongolian variation selectors, such as some Japanese names.
  - **How it refuses:** text that breaks the rule is refused with a message saying why, and hidden
    characters inside the text are never quietly stripped. Space and invisible characters around
    the text are trimmed. The first run, the Bot tab, the CLI and the Boss Cat tool all apply the
    rule. Profile text is also made one line before it enters a heartbeat prompt.
  - **What it does not do:** this narrows hidden text and does not rule it out. A persona can still
    hold a joiner after each letter, and spaces, the Braille blank, private-use and unassigned
    characters are not refused.
- **Model fields follow Cats Chat** (#118), in the wizard and in the Bot tab. They offer every
  catalog entry and its controls, mark defaults with `(default)`, and no longer translate catalog
  text. A cat bot created in the wizard from a catalog that names no default still starts at the
  first listed value, which for Grok is Extra High.
- **The Bot tab checks a provider only when asked** (#118). The check on each launch stays, for cat
  bots that start with the app. Choosing another provider in the tab no longer runs its helper, so a
  CLI outside the app's PATH, such as one under nvm when macOS or Linux started Cats Bot from the
  desktop, shows as not found until you press "Check this computer". This is read from the code and
  was not run.
- **"機器貓" and "cat bot"** (#114). The interface now calls a bot a cat bot in English and 機器貓
  in Traditional Chinese. Telegram's bot, the `bots` folder, code, IDs and the CLI keep "bot".
- **Primary buttons have dark text on the accent color** (#118), and the success green is slightly
  darker, in Settings as well as the wizard.
- **A floating Cat's menu closes when you click outside it** (#104). This was tested on Windows
  before the change merged. macOS carries the same change and has not run it.

## Updating existing bots

Bots keep their looks, settings and conversations, and do not go through the wizard. Names and
personas already stored keep working, including ones the new rule would refuse, and saving other
settings leaves them as they are. Only a new or changed value must follow the rule, so changing a
stored persona that holds hidden characters means retyping that part.

On Linux, a copy of 0.4.6 or 0.4.7 that an update or a failed update restarted, or a 0.4.8, 0.4.9
or 0.4.10 that one of them restarted and that has not been reopened since, must first be quit from
the tray and reopened from the applications menu, as the
[0.4.8 notes](https://github.com/cats-inc/cats-bot/releases/tag/v0.4.8) describe.

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.5.0-setup-<arch>.exe` and
  `Cats-Bot-0.5.0-portable-<arch>.exe`; updater `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.5.0-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.5.0-<arch>.deb`, with architecture-specific
  updater metadata.
- Per-platform receipts, `SHA256SUMS`, `Cats-Bot-v0.5.0-source.zip` and
  `Cats-Bot-v0.5.0-sources.json` accompany the installers.

Standard-profile expected trust: macOS **signed and notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), Linux
**n/a**. Receipts record actual trust and configured signature/notarization gates
enforce it. No unsigned override is selected.

Existing 0.4.x Windows NSIS and signed macOS installs using the same Developer ID
team retain their Check for Updates path. Nothing in the update code depends on the minor version;
this is read from the code and was not run. Linux uses the package manager.
Portable and unsigned Mac installations use manual replacement. There is no
automatic background installation. GitHub immutable releases and the active
`v*` tag protection remain enabled; publication attaches all assets before locking.

## Compatibility, backup and recovery

- **What moves the minor:** `cats-bot init`, the app's `--name` option, the core's `updateProfile`
  and the Boss Cat tool now refuse a new name or persona that breaks the rule above, where 0.4
  accepted it. A script passing such text needs to change it. The app's `--name` shows the error and
  quits. `cats-bot init`, `--name` and `updateProfile` also trim what they accept, where 0.4 stored
  it as given, and all of them now change a persona's line endings to LF, so a script reading the
  text back can see a difference. No other API, CLI or configuration contract changes.
- Profile schema 2, registry schema 1, hub/shell state and conversations keep their formats.
  No data migration or session reset is introduced.
- One new file can appear in the data root: `setup-draft.json` holds the wizard's input across a
  restart from the wizard. It is read once and removed on the next start. 0.4.10 does not read it.
- Before changing installations, stop Cats Bot and retain a copy of its data
  root (`~/.catsbot`, or the configured `CATS_BOT_HOME`) and Electron preferences.
  If installation fails, keep those directories intact and reinstall 0.5.0.
- The 0.4.10 installer reads the same data without conversion. Rolling back also restores the old
  first-run page and the looser name and persona handling. Both versions use the same Runtime.
