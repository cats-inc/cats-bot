# Cats Bot 0.5.0 — Standard Preview

This release replaces the first-run page with a three-page setup wizard. Nothing on the computer
is checked until you ask, and no script that changes it runs until you tick it. It starts the 0.5
line because `cats-bot init`, `updateProfile` and the Boss Cat tool now refuse names and personas
they used to accept. Stored data keeps its format.

The owner chose to publish this preview without clean-machine acceptance. The wizard has not yet
installed anything on a real machine, and it has not run on real macOS or Linux desktops. See the
acceptance boundary below before relying on it.

## Changes

- **A setup wizard for creating a cat bot** (#117, #118; ADR-015, SPEC-010). The first run, New
  cat bot and a Boss Cat's request now share one resizable window, with a minimum size of 800×600.
  - **Who it is:** name, look, provider and an optional personality. This page starts no process
    and scans no PATH, and no provider is preselected. Five personality presets replace the box's
    content, and Ctrl+Z restores it.
  - **This computer:** read-only checks for the chosen provider run only after "Check this
    computer". Every script that changes something has a tick box, unticked by default. Its
    details show what the helper reports it would do, the command that really runs, the script's
    SHA-256 and source commit, and a command for doing it by hand. "Apply" runs ticked rows one at
    a time from the top, with a fresh check after each.
  - **Sign-in and start:** "Open terminal and run" starts a new terminal with a fixed command per
    provider. No text from the page or a model reaches it, and no credential file is read. On a
    first run, starting Cats Bot at sign-in is a checkbox, ticked by default. Unticked leaves no
    login item.
  - **The log:** a read-only text area across the window's foot records each run's time, kind,
    full command and reported results. Any script run opens it. It closes after a success and stays
    open after a failure, and once you toggle it, it stays as you set it, except that a failure
    opens it. The hub's diagnostics record each finished run in fixed words only.
  - **PowerShell scripts on Windows** is now optional and listed last. It no longer blocks Codex or
    finishing. Declining it opens sign-in in Command Prompt.
- **One rule for a bot's name and persona** (#116). A name is one line of 1 to 40 UTF-16 units with
  at least one visible character. A persona is at most 4,000 units and may use line feeds and tabs.
  Neither may hold text you cannot see, such as control, bidirectional or tag characters, although
  a persona may keep the zero-width joiners that emoji and some scripts need. Text that breaks the
  rule is refused with a message saying why, and is never quietly stripped. The first run, the Bot
  tab, the CLI and the Boss Cat tool all apply it. Profile text is also made one line before it
  enters a heartbeat prompt.
- **Model fields follow Cats Chat** (#118), in the wizard and in the Bot tab. They offer every
  catalog entry and its controls except `request` scope, mark defaults with `(default)`, and reset
  the controls when the model changes. Where a catalog names no default, the first listed value is
  used, so a new Grok bot starts at Extra High. Catalog text is not translated.
- **The Bot tab checks a provider only when asked** (#118). The check on each launch stays.
- **"機器貓" and "cat bot"** (#114). The interface now calls a bot a cat bot in English and 機器貓
  in Traditional Chinese. Telegram's bot, the `bots` folder, code, IDs and the CLI keep "bot".
- **Primary buttons have dark text on the accent color** (#118), and the success green is slightly
  darker, in Settings as well as the wizard.
- **A floating Cat's menu closes when you click outside it** (#104), on Windows and macOS.

## Updating existing bots

Bots keep their looks, settings and conversations, and do not go through the wizard. Names and
personas already stored keep working, including ones the new rule would refuse, and saving other
settings leaves them as they are. Only a new or changed value must follow the rule.

On Linux, a copy of 0.4.6 or 0.4.7 that an update or a failed update restarted, or a 0.4.8, 0.4.9
or 0.4.10 that one of them restarted and that has not been reopened since, must first be quit from
the tray and reopened from the applications menu, as the [0.4.8 notes](v0.4.8.md) describe.

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.5.0-setup-<arch>.exe` and
  `Cats-Bot-0.5.0-portable-<arch>.exe`; updater `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.5.0-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.5.0-<arch>.deb`, with architecture-specific
  updater metadata.
- Per-platform receipts, `SHA256SUMS`, `Cats-Bot-v0.5.0-source.zip` and
  `Cats-Bot-v0.5.0-sources.json` accompany the installers.

Standard-profile expected trust: macOS **signed and notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), Linux
**n/a**. Receipts record actual trust and configured signature/notarization gates
enforce it. No unsigned override is selected.

Existing 0.4.x Windows NSIS and signed macOS installs using the same Developer ID
team retain their Check for Updates path. Nothing in the update code depends on the minor version;
this is read from the code and was not run. Linux uses the package manager.
Portable and unsigned Mac installations use manual replacement. There is no
automatic background installation. GitHub immutable releases and the active
`v*` tag protection remain enabled; publication attaches all assets before locking.

## Compatibility, backup and recovery

- **What moves the minor:** `cats-bot init`, the core's `updateProfile` and the Boss Cat tool now
  refuse a new name or persona that breaks the rule above, where 0.4 accepted it. A script passing
  such text needs to change it. No other API, CLI or configuration contract changes.
- Profile schema 2, registry schema 1, hub/shell state and conversations keep their formats.
  No data migration or session reset is introduced.
- One new file can appear in the data root: `setup-draft.json` holds the wizard's input across a
  restart from the wizard. It is read once and removed on the next start. 0.4.10 does not read it.
- Before changing installations, stop Cats Bot and retain a copy of its data
  root (`~/.catsbot`, or the configured `CATS_BOT_HOME`) and Electron preferences.
  If installation fails, keep those directories intact and reinstall 0.5.0.
- The 0.4.10 installer reads the same data without conversion. Rolling back also restores the old
  first-run page and the looser name and persona handling. Both versions use the same Runtime.
