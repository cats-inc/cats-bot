# Cats Bot 0.2.2 — Standard Preview

Connects Codex's native tool and plugin App consent to the Bot note. The bundled
Runtime recognizes marked MCP approval forms, including `cats-desktop` tool
requests and `node_repl` App requests, and returns note responses to the original
work item without another model message.

## Consent behavior

- The note shows the native request and bounded tool-input summary with **Allow**,
  **Decline** and **Cancel request**. Allow preserves the native App's grant
  semantics; it does not promise a one-use or persistent grant. Resolved receipts
  keep no prompt or answer values.
- Select an explicit provider policy in Settings → Bot with approval
  **on-request** or **untrusted** to receive interactive requests. Existing legacy
  policy can resolve to Codex `never` and suppress requests before the Bot sees
  them. Updating does not silently change a Bot's policy.
- Injected MCP tools now request approval under explicit interactive policies,
  including read-only calls. Legacy and explicit `never` behavior are unchanged.
- Cats desktop control still requires the Bot/conversation switches, a local
  owner turn and a separate per-App grant. Provider approvals do not supply that
  grant. Stop, observe-only apps and Windows permission-UI exclusions remain.

Expected standard trust with the configured shared credentials: macOS
**signed + notarized**, Windows **unsigned: no certificate** (including the desktop-control
helper), Linux **n/a**. Actual trust is recorded in the three platform build
receipts. Missing macOS credentials can produce unsigned output; that output
cannot self-update an existing signed macOS installation. The release also carries
updater metadata,
blockmaps, `SHA256SUMS`, `Cats-Bot-v0.2.2-source.zip` and its source manifest. The
complete source includes the Bot and its exact Runtime source.

When output trust matches this expectation, installed 0.2.1 Standard Previews
retain the same update eligibility: Windows
NSIS and signed macOS update in place through **Check for Updates**, Linux DEBs
use the package manager, and portable builds open the release page for manual
replacement. Quit other Bots sharing the installation first; the updating Bot
stops its Runtime before replacement. Unsigned macOS installations require a
manual signed installation before self-updates become available.

## Compatibility, upgrade and recovery

This is a compatible patch within Bots 0.2. Profile schema 2, the journal and
desktop-control configuration formats are unchanged; no new data migration is
required. Existing policy, conversations and app-grant boundaries are preserved.
Back up `~/.cats/bots` (or `CATS_BOTS_HOME`) before upgrading as usual. The 0.2.0
profile-backup and update-gate recovery procedures still apply. A failed update
must preserve the existing profile. Returning to 0.2.1 requires no data conversion
but loses this Codex consent fix; pre-0.2 readers still reject schema 2.
