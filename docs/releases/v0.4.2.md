# Cats Bot 0.4.2 — Standard Preview

A follow-up to the Windows wallpaper fix in 0.4.1: Cats Bot asks Explorer to
redraw the wallpaper only when a shown note uncovers it, and covers the cases
the 0.4.1 review found. A patch release with no data or contract changes.

## What changed

- **No requests for notes nobody could see (Windows).** Moving a hidden note
  off the wallpaper, or a hidden note going away, no longer asks Explorer to
  redraw the wallpaper, so it no longer briefly holds up the app.
- **Explorer restarts (Windows).** When Explorer restarts it takes down the
  notes on the desktop and wallpaper layers without telling Cats Bot. Cats Bot
  now forgets those notes, so a later window cannot inherit a gone note's style
  or layer, and no stray redraw request is sent for them.
- **Notes closed while Cats Bot quits (Windows).** A wallpaper note that closes
  while the app quits, for example because its bot was lost during the quit, is
  now hidden and its place redrawn as it closes. It still opens again next time.
- **Correction to the 0.4.1 notes.** They listed a known gap: a wallpaper note
  leaving a block when Cats Bot quits to install an update. A review of that
  path found that it already stops every bot first, and each bot's notes are
  hidden and their place redrawn before the app quits for the installer, so
  that entry overstated it. The update installation itself has not been run
  live.
- **What "shown" means.** A note counts as shown when its own window is
  visible, the same thing the shell reports, rather than also depending on the
  visibility of the Explorer window it sits in.

## Compatibility, upgrade and recovery

- **A patch.** No file format, registry field, CLI command or host contract
  changes; bot data, ids and the Boss Cat assignment are kept as they are.
- **From 0.3.x or 0.2.x.** Follow the 0.4.0 release notes; 0.4.1 and 0.4.2
  change nothing there.
- **Rollback.** 0.4.1 reads the same data. It asks Explorer to redraw the
  wallpaper for hidden notes too, and does not cover the Explorer-restart and
  quit cases above.

## Exact inputs and validation boundary

- **Bot:** version `0.4.2`. After the bump merges and CI on `main` passes on that
  commit, manually dispatch `bot-preview.yml` from it with `tag=v0.4.2`.
  - The guard refuses a commit without that passing run, and the build does not
    rerun the tests.
  - The workflow binds the commit to the tag, the packaged descriptors, the
    release body and the source manifest. Do not push a tag first.

    `363e784f2d0571522006797b01772be55384ecec4ae0bccb254eabd7b6783501`.
- **Setup helpers:** unchanged from 0.4.1 (cats-inc/cats-platform commit
  `cce4ff6e3ffefea684e4bc45fa72fb91f30a3fe7`).
- **Evidence.**
  - #80 passed typecheck, the test suite (362 tests), the build and candidate
    packages in CI on Windows, macOS and Ubuntu. The desktop host's rules are now
    tested against a fake Explorer, and each new rule makes its test fail when
    reverted.
  - On Windows 11 23H2 (classic shell), a development build in an isolated home
    was checked with a mark painted on Explorer's wallpaper window and read back
    from it. With a shown wallpaper note, hiding it, moving it to the desktop
    layer, deleting its conversation and quitting each cleared the mark. With a
    hidden one, moving it to the desktop layer or deleting its conversation left
    the mark, so no request was sent, and the note stayed hidden.
  - #80 had two independent reviews; the second one's findings are fixed in it.
- **Not exercised before this release:** a live Explorer restart (covered only by
  the fake-Explorer test), a live update installation, the modern Explorer of
  Windows 11 24H2 and later, picture or slideshow wallpapers, multiple monitors,
  an update from 0.4.1 with Check for Updates, and a first run on macOS, Linux or
  Windows ARM64.
