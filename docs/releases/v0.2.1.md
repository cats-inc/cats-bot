# Cats Bot 0.2.1 — Standard Preview

Adds Cats desktop control on Windows ([SPEC-006](../specs/SPEC-006-desktop-control-session-mcp.md),
[PLAN-006](../plans/PLAN-006-desktop-control-session-mcp.md)). The Bot can see and operate apps
the owner grants, only in turns the owner sends from this computer. Every other 0.2.0
behavior is unchanged.

## Desktop control (Windows)

- **Turning it on.** Settings → Bot → **Desktop control** turns it on for the Bot (off by
  default). Each conversation then has its own switch in its note, or `cats-bot desktop
  <conversation> --enable`.
- **Policy.** The Bot attaches the `cats-desktop` MCP server only when the Bot's explicit
  provider policy (Settings → Bot) asks for approval (`on-request` or `untrusted`).
- **Tools.**
  - Observe: `request_app_access`, `list_windows`, `screenshot_window`, `read_ui` and
    `open_app`.
  - Act: `click`, `invoke_element`, `type_text`, `key`, `scroll` and the two clipboard tools.
- **Who can use them.**
  - Owner messages sent from the note or `cats-bot say` can use the tools. Heartbeats,
    schedules and Telegram messages get `not_owner_present`.
  - The provider asks before every tool call.
  - The owner grants each app in the note or with `cats-bot desktop --grant`. Telegram text
    and provider approvals cannot grant an app.
- **What can be granted.** Terminals, IDEs and browsers can only be observed. The Bot, Cats
  Desktop and Windows consent and credential UI can never be granted. Grants are kept in memory
  only and end with Stop, switching off or a core restart.
- **While the Bot operates an app:**
  - The tray's first item becomes "Stop desktop control (app)", and the note shows a banner with
    Stop. `cats-bot desktop <conversation> --stop` stops it too.
  - Stop revokes the grants, cancels input in progress (typing included) and makes later calls
    answer `stopped`.
  - Input pauses with `operator_active` while the owner uses the keyboard or mouse. Every action
    answers `locked` while the screen is locked.
- **Privacy.**
  - The journal, receipts, logs and Telegram notices keep no screenshot bytes, UI values, typed
    text or clipboard content.
  - The transcript replaces each successful desktop tool result with a one-line summary, and
    replaces the text in `type_text` and `clipboard_write` inputs. Other tool inputs and
    error messages are kept as sent.
  - When the helper exits unexpectedly, the log keeps only exception types and stack frames.
- **Helper.** Windows packages carry `cats-desktop-control-windows`, a self-contained .NET 8
  helper for each architecture, at `resources/native/windows-desktop-control/`.
  - It runs as the current user and unelevated, and refuses elevated targets.
  - On macOS and Linux, desktop control shows as unavailable.

## Signing and updates

This release uses the standard signing profile:
- macOS: **signed + notarized** with the Developer ID certificate and notarization key shared
  with Cats Desktop.
- Windows: **unsigned: no certificate**. This includes the desktop control helper.
- Linux: **n/a**. The DEBs are unsigned and installed with OS package-manager authorization.

The platform receipts record the trust each build actually produced.

The 0.2.0 Standard Preview had the same trust on every platform, so installed 0.2.0 builds can
update with **Check for Updates** in the tray/floating cat menu or Settings → App:
- Windows NSIS installs and signed macOS installs update in place.
- Linux DEB installs go through the package manager.
- Portable builds open the release page for manual replacement.

Quit every other Bot using the installation before installing; the active Bot stops its
Runtime before replacement.

## Compatibility, upgrade and recovery

There is no data migration.
- **Profile.** Profiles stay at schema 2 and gain `desktopControl` (default
  `{ "enabled": false }`). 0.2.0 reads a 0.2.1 profile and ignores the field; if it rewrites
  the profile, the field is dropped.
- **Switches.** Conversation switches live in a new `desktop-control.json` in the Bot's data
  directory, which 0.2.0 does not read.
- **No downgrade migration.** Returning to 0.2.0 needs none; desktop control is simply absent
  there.

Back up the Bot data directory (`~/.cats/bots`, or the configured `CATS_BOTS_HOME`) before
upgrading as usual. The 0.2.0 recovery instructions for profiles and the update gate still
apply.

## Reproducible inputs and validation boundary

- **Bot version:** `0.2.1`. The workflow records the exact release commit in the release body,
  the packaged descriptors and the source manifest, and binds tag `v0.2.1` to that commit.
- **Runtime:** unchanged from 0.2.0. Version `0.6.2` from commit
  `e38e56bfd54fe783df22a5e0d914b14d186ee6bf` in `cats-inc/cats-runtime`, vendored as
  `vendor/cats-runtime-0.6.2-e38e56bf.tgz`. Runtime SHA-256:
  `84efc380cc3289584d1f27f8a16cc09b032d572284257ecad7e6becdb1df169d`.
- **Dependencies:** versions and tarball SHA-512 are fixed by `package-lock.json`.
- **Release assets:** digests are generated as `SHA256SUMS` and checked against the GitHub
  uploads before the draft becomes public.
- **macOS builds:** CI and release packages use the standard `macos-15-intel` runner, and the
  Universal output keeps both architecture slices. Signed macOS release jobs fetch notarization
  tickets over TCP on the disposable runner only.
- **Native acceptance (B7):** recorded in PLAN-006, 19 of 19 checks on Windows 11. It used real
  Claude Code 2.1.312 through the `cats-bot` CLI against an isolated test Bot. Input went only to
  a throwaway probe app, and a second helper read the probe back independently.
  - Every act call asked for approval first, and the input landed.
  - Each guard returned its code: `covered`, `password_field`, `observe_only` and
    `operator_active`.
  - CLI Stop while control was held made the next call answer `stopped`.
  - The transcript kept no typed text.
- **Not verified natively:**
  - turning on Settings → Bot → Desktop control in a running shell;
  - grant cards in a running note;
  - the note banner and tray in a running shell, and Stop from them;
  - the clipboard tools;
  - the lock pause;
  - Codex;
  - the helper from a packaged installer (B7 ran the development build).

Publication requires:
- the three-platform test/build/package matrix;
- complete-source and updater-metadata checks;
- the applicable signing checks, including Authenticode for the helper when Windows signing is
  configured.

Hosted Actions results and assets are the release evidence. Package tests are not an installed
update from 0.2.0 to 0.2.1.
