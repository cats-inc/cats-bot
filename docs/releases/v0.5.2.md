# Cats Bot 0.5.2 — Standard Preview

This release fixes the Windows provider check on a fresh account whose npm global
directory does not exist yet. It stays compatible with the 0.5 line and introduces
no data migration.

## Changes

- **Plan npm-folder setup and Codex installation together.** Native npm `ENOENT`
  stderr could terminate the Windows PowerShell 5.1 helper before it returned
  JSON, leaving the wizard with **The provider helper returned an unreadable
  result**. The shared helper now reports an absent package or unknown version
  for that missing-directory result, so setup can show both plans and apply them
  in order after the owner's confirmation. Read-only checks do not create folders
  or install packages.
  - An installed CLI with an unreadable npm version and Pi's superseded-package
    probes use the same handling. Native permission errors and PowerShell errors
    that merely mention `ENOENT` still propagate.
- **Back up an unreadable provider configuration before replacement.** The latest
  Runtime includes cats-runtime#213. A provider-selection save keeps an owner-only
  `providers.yaml.invalid-<timestamp>-<id>.bak` copy beside the unreadable file,
  retaining the five newest. If the copy fails, the save returns 409 and preserves
  the original. Missing or readable configurations do not create a backup.
- **Current producer pins.** Setup helpers and shared tools select Platform's
  latest merged source; cats-one remains at its latest source. The shared UI's
  source-content hash still matches its existing artifact.
- **Standard Intel macOS build host.** CI and Standard Preview use GitHub's
  `macos-26-intel` runner after the macOS 15 Intel pool failed to acquire a host.
  Both pipelines retain the complete test/package matrix, Universal x86_64 + arm64
  validation and the configured signing/notarization checks. Product architecture
  targets and update contracts do not change.

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.5.2-setup-<arch>.exe` and
  `Cats-Bot-0.5.2-portable-<arch>.exe`; updater `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.5.2-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.5.2-<arch>.deb`, with
  architecture-specific updater metadata.
- Per-platform build receipts, `SHA256SUMS`, `Cats-Bot-v0.5.2-source.zip` and
  `Cats-Bot-v0.5.2-sources.json` accompany the installers.

Standard-profile expected trust remains macOS **signed and notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), and Linux
**n/a**. The workflow records actual trust and enforces configured signature and
notarization gates. No unsigned override is selected.

Windows NSIS and signed macOS installations retain **Check for Updates**; Linux
uses the package manager. Portable and unsigned macOS copies use manual
replacement. Updates require an owner action. Existing Linux restart restrictions
in the deployment guide still apply. The workflow attaches every asset before
publishing the immutable prerelease with `make_latest=false`; no tag is pushed
in advance.

## Compatibility, backup and recovery

- Profile schema 2, registry schema 1, hub/shell state, conversations and session
  attachments keep their formats. No public API, CLI or configuration contract
  changes, data conversion or session reset is introduced. Runtime's extra backup
  files preserve an unreadable configuration; they do not change its format.
- Before changing installations, stop Cats Bot and processes using its data roots.
  Retain a copy of `~/.catsbot` (or the configured `CATS_BOT_HOME` and any overridden
  roots) and Electron preferences, such as `%APPDATA%\Cats Bot` on Windows.
- If installation or startup fails, keep those directories and any Runtime
  configuration backups intact and reinstall 0.5.2. Version 0.5.1 reads the same
  data without conversion and remains a rollback option. It restores the older
  provider check and Runtime behavior. Restore backups only with processes using
  those roots stopped.
