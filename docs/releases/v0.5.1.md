# Cats Bot 0.5.1 — Standard Preview

This release adds a Hub action to recover and arrange floating cat avatars, and
fixes a setup-wizard row that could ask for a restart before its change had run.
It stays compatible with the 0.5 line and introduces no data migration.

## Changes

- **Arrange all floating cats** (#122), directly below **Show floating cats** in
  the Hub tray menu, shows every running Cat's avatar and arranges them at the
  bottom-right of the monitor where the pointer is. Avatars wrap into rows when
  needed and their new positions are saved. The Chinese label is
  **將所有貓咪歸位排整齊**.
  - The action recreates each avatar's native window. This recovers the Windows
    case where an avatar stays hidden after its right-click menu is open during
    a virtual-desktop switch, even though the Hub/core still run and moving or
    hiding/showing the existing window does not help.
  - Repeated arrange requests and hiding while a replacement loads are handled.
    Other windows, conversations and core processes keep running. This is an
    explicit recovery action; the virtual-desktop trigger is not fixed.
- **Apply npm PATH setup plans before restarting** (#121). A read-only check's
  warning that its plan will need a restart no longer makes the wizard treat
  that restart as already required. The row stays selectable so the owner can
  apply the change first. Checks and already-applied changes retain their
  existing restart behavior.
- **Current producer pins.** Setup-helper provenance and shared maintenance-tool
  provenance now select their producers' current `main` commits. The copied
  file hashes are unchanged. Runtime and conversation UI already match their
  latest producer inputs, so their artifact pins stay unchanged.

  `Cats-Bot-v0.5.1-sources.json` accompany the installers.

Standard-profile expected trust remains macOS **signed and notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), and Linux
**n/a**. The workflow records actual trust and enforces the configured signature
and notarization gates. No unsigned override is selected.

Windows NSIS and signed macOS installations retain **Check for Updates**; Linux
uses the package manager. Portable and unsigned macOS copies use manual
replacement. Updates require an owner action, with no automatic background
installation. Existing Linux restart restrictions in the deployment guide still
apply. The workflow attaches every asset before publishing the immutable
prerelease with `make_latest=false`; no tag is pushed in advance.

## Compatibility, backup and recovery

- Profile schema 2, registry schema 1, hub/shell state, conversations and session
  attachments keep their formats. No public API, CLI or configuration contract
  changes, data conversion or session reset is introduced.
- Arranging avatars writes only the existing avatar position and visibility
  fields. Deliberately hidden avatars become visible when this action is used.
- Before changing installations, stop Cats Bot and retain a copy of its data
  root (`~/.catsbot`, or the configured `CATS_BOT_HOME`) and Electron preferences
  (`%APPDATA%\Cats Bot` on Windows).
- If installation fails, keep those directories intact and reinstall 0.5.1.
  Version 0.5.0 reads the same data without conversion, so it remains a rollback
  option. A rollback removes the new recovery action and restores the old setup
  behavior; retained avatar positions remain ordinary view state.
