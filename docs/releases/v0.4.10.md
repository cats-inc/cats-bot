# Cats Bot 0.4.10 — Standard Preview

This compatible 0.4 patch stops a Grok bot's next message failing with a conflict. The fix was
already in Cats Runtime when 0.4.9 was prepared, and 0.4.9 left it out.

## Changes

- **A Grok bot's next message no longer fails with HTTP 409** (cats-inc/cats-runtime#212). Grok
  writes its session files before it reports its session ID at the end of a turn. Runtime could
  match those files by working directory first, which invalidated the new session's record of its
  content. The next message then failed with `Runtime rejected the message (HTTP 409,
  skill_content_profile_conflict)`. Runtime now waits for Grok's exact session ID, as it already
  did for Codex.
- **Releases now check their Runtime** (#112). This affects how Cats Bot is released, not how it
  runs. Before any build, the preview refuses a Runtime commit that is not on Runtime `main`, or
  one lacking changes there that the release notes do not list as left out. Cats Desktop runs the
  same check (cats-inc/cats-platform#380).

## Updating existing bots

Bots keep their looks, settings and conversations.

On Linux, a copy of 0.4.6 or 0.4.7 that an update or a failed update restarted, or a 0.4.8 that
one of them restarted and that has not been reopened since, must first be quit from the tray and
reopened from the applications menu, as the [0.4.8 notes](v0.4.8.md) describe.

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.4.10-setup-<arch>.exe` and
  `Cats-Bot-0.4.10-portable-<arch>.exe`; updater `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.4.10-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.4.10-<arch>.deb`, with architecture-specific
  updater metadata.
- Per-platform receipts, `SHA256SUMS`, `Cats-Bot-v0.4.10-source.zip` and
  `Cats-Bot-v0.4.10-sources.json` accompany the installers.

Standard-profile expected trust: macOS **signed and notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), Linux
**n/a**. Receipts record actual trust and configured signature/notarization gates
enforce it. No unsigned override is selected.

Existing 0.4.x Windows NSIS and signed macOS installs using the same Developer ID
team retain their Check for Updates path. Linux uses the package manager.
Portable and unsigned Mac installations use manual replacement. There is no
automatic background installation. GitHub immutable releases and the active
`v*` tag protection remain enabled; publication attaches all assets before locking.

## Compatibility, backup and recovery

- Profile schema 2, registry schema 1, hub/shell state and conversations keep their formats.
  No data migration or session reset is introduced, and the Bot's API does not change.
- Before changing installations, stop Cats Bot and retain a copy of its data
  root (`~/.catsbot`, or the configured `CATS_BOT_HOME`) and Electron preferences.
  If installation fails, keep those directories intact and reinstall 0.4.10.
- The 0.4.9 installer reads the same data without conversion. Rolling back also restores the
  previous Runtime artifact, and with it the Grok failure.

## Exact inputs and validation boundary

- **Bot:** version 0.4.10 from the merged bump commit selected for manual dispatch.
  After CI passes on that exact `main` commit, dispatch `bot-preview.yml` with
  `tag=v0.4.10`. The workflow creates the tag at publication; do not push it first.
  It verifies packaged identities, complete source/assets and checksums before
  publishing the Standard Preview with `make_latest=false`.
- **Runtime:** 0.6.2, source
  `c1d0111dd8d2bd4668e0d6d4f93afc20af9bd77b`, the head of Runtime `main` when this was prepared,
  changed from 0.4.9's `f53a2058` under the same package version. Artifact
  `vendor/cats-runtime-0.6.2-c1d0111d.tgz`, SHA-256
  `0a66ac17326047261baefd8f9fe4cc7e972659fc3560720873cc609968d88936`. The two artifacts differ
  only in `SessionRegistry.js` and its two source maps. 0.4.9's source was the unmerged branch
  head of cats-inc/cats-runtime#211. Its merged commit has an identical tree, so the fix above is
  the only code that changes.
- **Why 0.4.9 lacked the fix:** cats-inc/cats-runtime#212 merged about 3.5 hours before the 0.4.9
  bump, which reused the pin from #107 without comparing it to Runtime `main`. The check in #112
  now refuses that.
- **Shared conversation UI:** `@cats-inc/platform-ui-web` 0.1.0, artifact
  `vendor/platform-ui-web-0.1.0-957e4717942c.tgz`, SHA-256
  `363e784f2d0571522006797b01772be55384ecec4ae0bccb254eabd7b6783501`, unchanged from 0.4.9.
- **Setup helpers:** Platform source
  `7b3f94ef822860f1ceb34398d93d8245f8fd39d0`, with all 35 per-file hashes in
  `assets/setup/provenance.json`, unchanged from 0.4.9.
- **Other shared tooling:** `scripts/shared-tools.provenance.json` now pins cats-one `d86fd805`
  and Platform `9e54a282`, both on their `main`. It adds `scripts/shared/source-selection.mjs`.
  The other shared files keep their bytes.
- **Existing evidence:**
  - With this pin, a full `npm test` on Windows after a fresh `npm ci` passed 487 tests, with 9
    skipped and none failed. It includes the packed Runtime hosting Grok tools and approvals with
    a scripted fixture. The bump's own hosted CI runs the same suite on Linux, Windows and macOS.
  - #111, also new since 0.4.9, changes only a test and its documentation.
  - #112 passed hosted CI on Linux, Windows and macOS, and had independent review. So did the
    shared check in cats-inc/cats-platform#380, whose first revision the review found could pass
    when it should refuse. That is fixed with tests.
  - Rebuilding `f53a2058` on Windows with the refresh script's steps reproduced 0.4.9's Linux ARM64
    artifact byte for byte, so this artifact does not depend on the machine that built it.
  - cats-inc/cats-runtime#212 reports 145 passing Runtime tests, new Grok regressions that failed
    before the fix, and an installed Windows Bot that resent a failed message successfully with
    the matching compiled fix applied. None of that was repeated for this release.
- **The Runtime check's first run:** the workflow step added in #112 runs only on a real dispatch,
  and this release is its first. Its logic was replayed against real Runtime history. A failure
  of the step stops in the guard job, before a draft or any build exists.
- **Acceptance boundary:** these checks do not establish a packaged install, an installed
  0.4.9-to-0.4.10 upgrade, a real return to 0.4.9, an in-app update from 0.4.10 to a later version,
  real macOS and Linux desktops, or the fix with a real Grok CLI in this build. Bot's own tests use
  scripted fixtures. The bump's CI and release workflow enforce their own exact-source gates; their
  hosted records carry the outcomes.

Publication results: the `v0.4.10` GitHub Standard Preview, platform receipts and
its Actions run. Publication verification checks immutable status, tag source,
public asset hashes, update metadata and release attestation.
