# Cats Bot 0.2.3 — Standard Preview

Keeps the Bot note readable after native provider requests. Finished requests
no longer pile up as cards under the conversation, and a long tool name no
longer widens the note.

## Note behavior

- The note shows only provider requests that are still open: those waiting for
  the owner and those whose answer is being sent, at the same place near the
  current turn. 0.2.2 also kept the
  last four finished requests as full cards after the transcript. Their receipts
  are redacted, so each said only "resolved"; together they filled the note and
  buried the latest reply. Finished receipts remain in the core and
  `cats-bot interactions`.
- A tool name reported as a whole command line (Codex) is cut with an ellipsis,
  with the full name on hover, instead of adding a horizontal scrollbar.
- Consent semantics, policies, Cats desktop control grants and the receipt store
  are unchanged.

Expected standard trust with the configured shared credentials: macOS
**signed + notarized**, Windows **unsigned: no certificate** (including the desktop-control
helper), Linux **n/a**. Actual trust is recorded in the three platform build
receipts. Missing macOS credentials can produce unsigned output; that output
cannot self-update an existing signed macOS installation. The release also carries
updater metadata, blockmaps, `SHA256SUMS`, `Cats-Bot-v0.2.3-source.zip` and its
source manifest. The complete source includes the Bot and its exact Runtime source.

When output trust matches this expectation, installed 0.2.2 Standard Previews
retain the same update eligibility: Windows NSIS and signed macOS update in place
through **Check for Updates**, Linux DEBs use the package manager, and portable
builds open the release page for manual replacement. Quit other Bots sharing the
installation first; the updating Bot stops its Runtime before replacement.
Unsigned macOS installations require a manual signed installation before
self-updates become available.

## Compatibility, upgrade and recovery

This is a compatible patch within Bots 0.2 that changes only the note renderer.
Profile schema 2, the journal, the provider-interaction receipt store and
desktop-control configuration formats are unchanged; no data migration is
required. Back up `~/.cats/bots` (or `CATS_BOTS_HOME`) before upgrading as usual.
The 0.2.0 profile-backup and update-gate recovery procedures still apply. A failed
update must preserve the existing profile. Returning to 0.2.2 requires no data
conversion and brings back the finished-request cards; pre-0.2 readers still
reject schema 2.

  `0387f867b15543aba78e8b91858cd179fec125e0376c70468ac67344e3f63154`. The lockfile
  fixes its SHA-512 integrity and all dependencies.
- **Feature evidence:** the note change (#46) passed typecheck, build, 194 tests
  including a new regression test for the shown requests, and the three-platform
  CI matrix. An isolated Electron note with the scripted Codex fixture, driven
  over CDP on Windows, showed each of five live requests and removed it after the
  answer while the core kept all five receipts. The fixture raises `user_input`
  requests; the filter depends on request status, not kind. The long-name layout
  was checked with an injected tool card, not a real Codex transcript entry.
- **Hosted gates:** the bump PR and release workflow run full tests and the
  three-platform build/package matrix, validate both macOS architecture slices,
  Windows helper architecture/licenses, complete source, updater asset names,
  sizes and hashes, applicable signatures and provenance before publication.
- **Upgrade scope:** source fixtures and package checks are not an installed
  0.2.2-to-0.2.3 upgrade test on Windows/macOS/Linux. Publication results are the
  `v0.2.3` GitHub prerelease and its Actions run.
