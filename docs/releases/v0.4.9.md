# Cats Bot 0.4.9 — Standard Preview

This compatible 0.4 patch lets each bot have its own Cat, raises the bot limit to five, and
gives a silent Antigravity turn 120 seconds instead of 30.

## Changes

- **Ten looks for the Cat** (#108, #109). Ginger tabby (the original, and the default),
  Tuxedo, Siamese, Calico, Gray fold, Brown tabby, White tabby, Black, Persian and Bengal.
  They differ in colour, pattern and face shape.
- **Choose a look when you set up a bot, or later** (#108, #109). The first-run page, the New
  bot page and a bot's Bot tab all offer the ten. The floating Cat, the bot's settings window
  and its replies in a note show the choice, and a saved change appears at once. It does not
  restart the bot or start new sessions.
- **A new bot gets a look no other bot uses** (#108). The New bot page opens on it, and a bot
  created without the page, by the Boss Cat or by `cats-bot init`, gets one too. Archived bots'
  looks are avoided while another is free. You can still give several bots the same look.
- **Up to five bots** (#108). Existing installations move from three to five when they open.
  Archived bots still do not count.
- **Antigravity turns are no longer stopped after 30 seconds of silence** (#107). The pinned
  Runtime now allows 120 seconds of silence after a legacy CLI turn's first event, and
  provider progress resets that time. It still allows 30 seconds before the first event.

## Updating existing bots

Bots you already have keep the original Cat until you choose another, so an upgraded
installation can show several identical Cats. Their settings and conversations are unchanged.

On Linux, a copy of 0.4.6 or 0.4.7 that an update or a failed update restarted, or a 0.4.8 that
one of them restarted and that has not been reopened since, must first be quit from the tray and
reopened from the applications menu, as the [0.4.8 notes](v0.4.8.md) describe.

Standard-profile expected trust: macOS **signed and notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), Linux

enforce it. No unsigned override is selected.

Portable and unsigned Mac installations use manual replacement. There is no
automatic background installation. GitHub immutable releases and the active
`v*` tag protection remain enabled; publication attaches all assets before locking.

## Compatibility, backup and recovery

- Profile schema 2, registry schema 1, hub/shell state and conversations keep their formats.
  No data migration or session reset is introduced.
- `profile.json` gains an optional `avatar`. A missing or unknown value reads as the original
  Cat, and reading a profile does not rewrite it.
- `bots.json` keeps `maxBots`. A stored 3, the value every earlier version wrote, reads as 5,
  and the next registry write records it. Any other stored positive whole number is kept. A 3
  set by hand cannot be told apart and also reads as 5.
- Additions to the API: `status` and `getProfile` from the host channel return `avatar`, the
  event stream (also `cats-bot run --json`) gains `profile.updated`, and `updateProfile` accepts
  `avatar`. No command or flag is added.
- Before changing installations, stop Cats Bot and retain a copy of its data
  root (`~/.catsbot`, or the configured `CATS_BOT_HOME`) and Electron preferences.
  If installation fails, keep those directories intact and reinstall 0.4.9.
- The 0.4.8 installer reads the same data without conversion. It drops `avatar` when it next
  saves a profile, so those bots show the original Cat after returning to 0.4.9. It keeps a
  stored `maxBots` of 5, so five bots keep running. Rolling back also restores the previous
  Runtime artifact and its 30-second limit.
