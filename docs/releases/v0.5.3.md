# Cats Bot 0.5.3 — Standard Preview

This compatible 0.5 patch repairs installation on a clean Windows account after
the owner accepts administrator permission. It introduces no data migration.

## Changes

- **Preserve elevated Node.js installer paths.** A Cats Bot installation path
  containing spaces could be split when PowerShell launched the administrator
  helper. Native arguments now preserve spaces, Unicode, quotes and trailing
  backslashes. Missing, unreadable or invalid result relays and cancelled launches
  produce structured errors instead of an unreadable helper result.
- **Preserve provider installer temporary paths.** Antigravity, Grok and Muse
  use the same argument serialization when launching a temporary PowerShell
  script. Real child exit codes and errors remain available.
- **Treat MSI 3010 as successful installation needing a Windows reboot.** Node.js
  returns an explicit machine-restart result. The current Hub setup session keeps
  that advice through fresh reads and later setup actions, even if Node already
  works. An unavailable Node offers a Windows restart hint without another install
  or a Restart Cats Bot button; usable tools may continue. Real check failures
  remain failures. Nothing reboots Windows automatically or writes a new persistent
  reboot marker. Ordinary PATH refresh retains its existing behavior.
- **Make Node.js DryRun safe.** Windows, macOS and Linux Node Apply/Upgrade/Force
  previews return plans before download, elevation or installation.
- **Keep setup summaries accurate.** A successful installation followed by a
  recheck continues to count as a change. The private Electron fixture now waits
  for app readiness without a top-level-await deadlock and waits for painting
  before hidden-window screenshots.

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.5.3-setup-<arch>.exe` and
  `Cats-Bot-0.5.3-portable-<arch>.exe`, with `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.5.3-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.5.3-<arch>.deb`, with
  architecture-specific updater metadata.
- Per-platform receipts, `SHA256SUMS`, `Cats-Bot-v0.5.3-source.zip` and
  `Cats-Bot-v0.5.3-sources.json` accompany the installers.

Standard-profile expected trust is macOS **signed + notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), and Linux
**n/a**. Configured native signature/notarization checks gate publication and
receipts record actual trust. No unsigned override is selected.

Windows NSIS, signed macOS using the same Developer ID team, and Linux DEB retain
their update paths. Portable and unsigned macOS installations require manual
replacement. Updates require an owner action; the existing Linux restart
restrictions still apply. The workflow attaches every asset before publishing
the immutable prerelease with `make_latest=false`, creating its tag at publication.

## Compatibility, backup and recovery

Profile schema 2, registry schema 1, conversations, hub/shell state, session
attachments, public API, CLI and configuration retain their formats. Existing
0.5 profiles need no conversion or reset. Before installation, stop Cats Bot and
processes using its data roots, and back up `~/.catsbot` (or configured
`CATS_BOT_HOME` and overrides) and Electron preferences, such as `%APPDATA%\Cats Bot`.
Keep existing Runtime configuration backups.

If installation or startup fails, preserve those directories and reinstall 0.5.3
or return to 0.5.2 without data conversion. Returning restores its previous setup
behavior. Restore backups only with all processes using those roots stopped.
