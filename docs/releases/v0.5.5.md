# Cats Bot 0.5.5 — Standard Preview

This compatible 0.5 patch lets Cats Bot start after a Windows restart that left
its locks behind, and lets the owner create a Cat while Codex's Windows sandbox
initialization is incomplete. It introduces no data migration.

## Changes

- **Start after a restart.** Windows ends Cats Bot at shutdown without running
  its quit handlers, so its lock files stay behind, and after the restart another
  process can hold the PID they name. Cats Bot then refused to start with
  "Another Cats Bot (…, pid N) manages the cat bots", although none ran. The
  check dates from 0.3.0; starting at sign-in made a reused PID likely. The hub
  lock, each Cat's instance lock and the registry's write lock now record their
  writer's process identity: the creation time on Windows, the boot id and start
  time on Linux, the start time on macOS. A lock whose PID another process now
  uses is taken over. No clock is compared, so a clock change or a long sleep
  cannot make a lock in use look abandoned. A lock is removed only while it
  still holds what was judged, so a hub starting at the same moment keeps its
  own. (cats-bot#129)
- **Update after a restart.** The update leases and install marker follow the
  same rule, so a lease left by a restart no longer stops an update with "Quit
  the other Cats Bot instances". (cats-bot#129)
- **Create a Cat while Codex initialization is incomplete.** Codex sandbox
  readiness on Windows is now advice. The last setup page keeps **Open Codex
  first-time setup** and **Check again**, but **Create and start** no longer
  waits for readiness once the required CLI components are installed. Both
  creation paths still recheck the installation. Runtime keeps refusing a turn
  whose actual permissions differ from those requested. (cats-bot#128)

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.5.5-setup-<arch>.exe` and
  `Cats-Bot-0.5.5-portable-<arch>.exe`, with `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.5.5-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.5.5-<arch>.deb`, with
  architecture-specific updater metadata.
- Per-platform receipts, `SHA256SUMS`, `Cats-Bot-v0.5.5-source.zip` and
  `Cats-Bot-v0.5.5-sources.json` accompany the installers.

Standard-profile expected trust is macOS **signed + notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), and Linux
**n/a**. Configured native signature/notarization checks gate publication and
receipts record actual trust. No unsigned override is selected.

Windows NSIS, signed macOS using the same Developer ID team, and Linux DEB retain
their update paths. Portable and unsigned macOS installations require manual
replacement. Updates require an owner action; existing Linux restart restrictions
still apply. The workflow attaches all assets before publishing the immutable
prerelease with `make_latest=false`, creating its tag at publication.

## Updating from 0.5.4 or earlier

The update to 0.5.5 runs the installed version's checks, which still have the
old rule:

- If Cats Bot refuses to start after a restart, close the dialog, delete
  `hub.lock.json` in `~/.catsbot` (or the configured `CATS_BOT_HOME`), and start
  it again.
- If **Update** stops with "Quit the other Cats Bot instances before installing
  this update" while no other Cats Bot runs, quit Cats Bot, delete the
  `pid-*.json` files in `%APPDATA%\Cats Bot\installations\<id>\`, reopen it and
  update again. Alternatively, install `Cats-Bot-0.5.5-setup-<arch>.exe`
  yourself.

## Compatibility, backup and recovery

Profile schema 2, registry schema 1, conversations, hub/shell state, session
attachments, public API, CLI and configuration retain their formats. Lock files,
update leases and the install marker gain optional fields (`identity`, and
`writtenAt` in leases and the marker) that 0.5.4 and earlier ignore. Locks from
0.5.4 and earlier carry no identity: Windows judges them by time, and other
systems keep them while their PID is alive, as before. Where the identity cannot
be read, a lock with a live PID is kept, as before. Existing 0.5 profiles need no
conversion or reset. Before installation, stop Cats Bot and processes using its
data roots, and back up `~/.catsbot` (or configured `CATS_BOT_HOME` and
overrides) and Electron preferences, such as `%APPDATA%\Cats Bot`. Keep existing
Runtime configuration backups.

If installation or startup fails, preserve those directories and reinstall 0.5.5
or return to 0.5.4 without data conversion. Returning restores 0.5.4's lock check,
including its refusal after a restart, and its setup behavior. Restore backups
only with all processes using those roots stopped.
