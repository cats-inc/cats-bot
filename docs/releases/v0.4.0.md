# Cats Bot 0.4.0 — Standard Preview

The coordinator role becomes the **Boss Cat** (主控貓), Cats Bot Settings manages
the app and every bot from one window, and a clean Windows machine can set up any
of the five providers from the setup page. This is a new minor: a hub registry
field and a CLI command are renamed.

## What changed

- **Boss Cat.** The bot that hands work to other bots and asks to create, start
  or stop them is the Boss Cat in the interface, the CLI and the hub files. One
  bot holds the role at a time.
  - The `bots.json` field `coordinator` is now `bossCat`.
  - `cats-bot hub coordinator` is now `cats-bot hub boss-cat <id>` (or
    `--clear`).
- **Ids from a name end in `-catsbot`.** A bot named Mochi gets
  `mochi-catsbot`, and a taken id gets `-2`, `-3` and so on. An id given with
  `--id` is used as given, and existing bots keep their ids.
- **Cats Bot Settings.** The hub has its own Settings window. The tray offers it
  as **Settings…** with any number of bots, and it opens by itself when no bot
  runs.
  - **General:** the app language, start at login, the version and updates, and
    the data folder.
  - **Bots:** the only place that creates, starts, stops, archives and orders
    bots.
  - A bot's own window keeps its bot, notes, life and Telegram tabs. The former
    App tab is **Details**, and the tray item is **Bot settings…**.
- **Setting up a provider on a clean machine.**
  - After an install, the page checks the step again and moves on. A restart or
    relaunch shows only while that check cannot confirm the step, so **Create and
    start** no longer waits for **Check again**.
  - The provider hint follows an install. Sign-in lines for all five providers
    are in Traditional Chinese, and a help line shows once.
  - A declined UAC prompt shows 「需要管理員授權」.
  - A bot's settings can reinstall a CLI that was removed.
  - **Codex on Windows** gets an **Allow PowerShell scripts** step after the npm
    folder. It sets your own execution policy to RemoteSigned, so `codex` and
    `codex login` run in a PowerShell terminal, and Codex waits for it.
  - Claude Code's folder is added to your PATH, so a new terminal can run
    `claude`. Setup downloads use TLS 1.2 where Windows PowerShell 5.1 still
    defaults to TLS 1.0.
  - When the Boss Cat asks for a bot whose provider is not set up, the New bot
    window opens filled in, after you consent. Names are limited to 40
    characters. While a New bot window is open, such a request is refused.

## Compatibility, upgrade and recovery

- **A new minor.** Two contracts change, and Cats Bot is pre-launch, so neither
  is migrated:
  - A 0.3 Boss Cat assignment, stored as `coordinator`, is not carried over.
    After updating, no bot holds the role until you assign it on the Bots page
    or with `cats-bot hub boss-cat <id>`. The registry keeps schema 1, and its
    bots, order, limits and archive are read as before.
  - Scripts that call `cats-bot hub coordinator` must call `cats-bot hub
    boss-cat`.
- **Bot data is unchanged.** Each bot's folder, notes, schedules, Telegram
  settings and id stay as they are. A 0.3 core that is still running when the
  0.4.0 hub starts is restarted; updating stops every bot first, so this applies
  only after a crash.
- **From 0.2.x.** There is still no upgrade. Follow the steps in the 0.3.0
  release notes: turn off Start at login in 0.2.x, uninstall it without
  updating, then install 0.4.0.
- **Rollback.** 0.3.1 reads the same registry and ignores `bossCat`, so no bot
  holds its coordinator role there; ids ending in `-catsbot` stay valid. No data
  needs converting.
