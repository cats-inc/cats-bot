# Cats Bot 0.5.4 — Standard Preview

This compatible 0.5 patch guides native Windows Codex users through first-time
initialization after login, before creating a Cat. It introduces no data migration.

## Changes

- **Complete Codex's own setup after login.** The last setup page offers
  **Open Codex first-time setup** when initialization is incomplete or cannot be
  verified. It opens a real Command Prompt in an owned empty temporary workspace.
  Complete Codex's prompts, exit Codex, and press **Check again**. Codex handles
  sandbox choices and administrator permission. PowerShell scripts remains optional.
- **Check readiness before creating a Cat.** Installation can proceed to sign-in
  without sandbox readiness. Both first-run creation paths require a fresh native
  Codex check before creating the Cat; opening the terminal alone is insufficient.
  Existing checks for other providers and platforms retain their behavior.
- **Keep checks read-only and bounded.** The probe resolves the same native CLI,
  including npm launchers and Node/Electron architecture differences. It sends only
  initialize, initialized and windowsSandbox/readiness, without creating a thread,
  starting a model turn, modifying provider configuration or installing a sandbox.
  Cancellation and shutdown wait for owned process cleanup. Runtime retains its
  actual-session permission guard.

## Downloads, signing and updates

- Windows x64/ARM64: `Cats-Bot-0.5.4-setup-<arch>.exe` and
  `Cats-Bot-0.5.4-portable-<arch>.exe`, with `latest.yml`.
- macOS Universal (Intel x64 + Apple Silicon ARM64):
  `Cats-Bot-0.5.4-universal.dmg`, updater ZIP and `latest-mac.yml`.
- Debian/Ubuntu amd64/ARM64: `Cats-Bot-0.5.4-<arch>.deb`, with
  architecture-specific updater metadata.
- Per-platform receipts, `SHA256SUMS`, `Cats-Bot-v0.5.4-source.zip` and
  `Cats-Bot-v0.5.4-sources.json` accompany the installers.

Standard-profile expected trust is macOS **signed + notarized**, Windows
**unsigned: no certificate** (including the desktop-control helper), and Linux
**n/a**. Configured native signature/notarization checks gate publication and
receipts record actual trust. No unsigned override is selected.

Windows NSIS, signed macOS using the same Developer ID team, and Linux DEB retain
their update paths. Portable and unsigned macOS installations require manual
replacement. Updates require an owner action; existing Linux restart restrictions
still apply. The workflow attaches all assets before publishing the immutable
prerelease with `make_latest=false`, creating its tag at publication.

## Compatibility, backup and recovery

Profile schema 2, registry schema 1, conversations, hub/shell state, session
attachments, public API, CLI and configuration retain their formats. Existing
0.5 profiles need no conversion or reset. Before installation, stop Cats Bot and
processes using its data roots, and back up `~/.catsbot` (or configured
`CATS_BOT_HOME` and overrides) and Electron preferences, such as `%APPDATA%\Cats Bot`.
Keep existing Runtime configuration backups.

If installation or startup fails, preserve those directories and reinstall 0.5.4
or return to 0.5.3 without data conversion. Returning restores its previous setup
behavior. Restore backups only with all processes using those roots stopped.
For a Cat already reporting the effective-permission mismatch, complete official
Codex initialization, fully quit and reopen Cats Bot, then retry the Cat; the
failed provider session is recreated. This release does not silently alter Codex
permissions.
