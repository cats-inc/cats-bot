# Cats Bot 0.5.6 — Standard Preview

This compatible 0.5 patch synchronizes the npm-provider installation repair from
Cats Desktop. It introduces no data migration or new provider.

## Changes

- **Use npm's normal engine policy.** The Codex installer no longer adds
  `--engine-strict` on top of npm's defaults. An explicit user engine policy is
  preserved; the separate npm self-update retains its engine guard. The shared
  producer fix also repairs Desktop's Cline installation on current Node LTS.
- **Approve the selected CLI script once.** On npm versions that support script
  approvals, installation approves only the selected package at its resolved exact
  version for that invocation. Older npm retains its normal behavior. No persistent
  npm approval or blanket transitive-script authorization is added; user policies
  such as `ignore-scripts` remain effective.
- **Verify the executable.** Installation requires both the expected npm package
  version and a bounded successful CLI `--version` response before reporting ready.
  Empty output, a stale executable, a nonzero exit or timeout is a failure. The
  packaged Windows helper includes its process-support dependency; the isolated
  missing-prefix regression fixture now copies that same dependency closure.
- **Keep setup and execution separate.** Codex initialization remains advisory for
  creation, as in 0.5.5. Runtime still enforces actual-session permissions; finish
  Codex's own first-time setup before chatting when required.

## Compatibility, backup and recovery

Profile schema 2, registry schema 1, conversations, hub/shell state, session
attachments, lock identity, public API, CLI and configuration retain their formats.
Existing 0.5 profiles need no conversion or reset. Before installation, stop Cats
Bot and processes using its data roots, and back up `~/.catsbot` or configured
`CATS_BOT_HOME`/overrides, Electron preferences such as `%APPDATA%\Cats Bot`, and
existing Runtime configuration backups.

If installation or startup fails, preserve those directories and reinstall 0.5.6
or return to 0.5.5 without data conversion. Returning restores its prior installer
behavior. Restore backups only with all processes using those roots stopped.

## Standard distribution and trust

Windows x64/arm64 receive NSIS installers and portable EXEs; macOS receives a
universal x64/arm64 DMG and updater ZIP; Linux amd64/arm64 receive DEBs. Expected
Standard trust is macOS **signed + notarized**, Windows **unsigned: no
certificate**, Linux **n/a**. Native checks and per-platform receipts establish
actual trust. NSIS, same-team signed macOS and Linux DEB retain their update paths;
portable and unsigned macOS installations require manual replacement.

Publication results: the `v0.5.6` GitHub Standard Preview, platform receipts and
Actions run. Verification checks immutable status, tag source, complete public
assets and hashes, updater metadata and release attestation.
