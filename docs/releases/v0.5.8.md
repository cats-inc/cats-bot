# Cats Bot 0.5.8 — Standard Preview

This compatible 0.5 update preserves conversations across host restarts, adds
native note input and macOS desktop layers, and gives own initiative a daily
rhythm. It introduces no mandatory data conversion or new provider.

## Changes

- **Continue the same native conversation.** Startup, worker exit and ordinary
  sleep inspect and resume compatible saved Runtime/native IDs, with fresh host
  and MCP descriptors and recognizable native names. Startup/wake sends no model
  turn. Temporary failures keep the saved mapping. Confirmed loss and the
  existing repeated-failure detector share a persisted, one-attempt replacement
  fence; partial output is never replayed. (cats-bot#139, cats-bot#149,
  cats-runtime#214, cats-runtime#215)
- **A daily rhythm for own initiative.** Assist and companion modes, rest hours,
  home sleep and unanswered-message back-off keep proactive turns bounded. The
  Boss Cat assists by default; other Cats keep company. Owner messages still
  reach the selected conversation during rest hours. (cats-bot#138, cats-bot#142)
- **More ways to use a note.** Notes support file attachments, region
  screenshots and native dictation. macOS notes can sit on the desktop or
  wallpaper. Permission notices open the matching macOS System Settings pane.
  Native input and desktop control retain their permission gates.
  (cats-bot#136, cats-bot#140, cats-bot#141, cats-bot#147)
- **Clearer recovery and settings.** Retry the owner's failed message from its
  bubble, show a failed turn's error once, and manage agent CLIs with the same
  install/repair rows used by setup. Node 24.22 socket priority errors no longer
  abort requests, and macOS architecture checks use `lipo -archs`.
  (cats-bot#137, cats-bot#143, cats-bot#144, cats-bot#146)

## Compatibility, backup and recovery

Profile schema 2, registry schema 1, version-1 conversations, CLI and provider
configuration remain compatible. Optional session-recovery and heartbeat fields
load older records without a bulk rewrite and use the existing atomic writer on
updates. The new Boss Cat status-board proposal is documentation, not a shipped
feature. Existing native history is retained.

Before installation, stop Cats Bot and processes using its roots, then back up
`~/.catsbot` or configured `CATS_BOT_HOME`/overrides, Electron preferences such as
`%APPDATA%\Cats Bot`, and Runtime configuration backups. On installation/startup
failure, preserve those directories and reinstall 0.5.8 or return to 0.5.7.
Also back up `.cats-attachments/` in each configured Bot working directory:
attachments and region screenshots may live outside the Bot/profile roots, and
restoring only the transcript does not restore those files.
Returning restores the former restart/session and note behavior and no longer
provides this release's recovery fence. Restore backups only while all processes
using those roots are stopped; no data conversion is needed for this release.

## Standard distribution and trust

Windows x64/arm64 receive NSIS installers and portable EXEs; macOS receives a
universal x64/arm64 DMG and updater ZIP; Linux amd64/arm64 receive DEBs. Expected
Standard trust is macOS **signed + notarized**, Windows **unsigned: no
certificate**, Linux **n/a**. Native checks and per-platform receipts establish
actual trust. NSIS, same-team signed macOS and Linux DEB retain their update paths;
portable and unsigned macOS installations require manual replacement.

Publication results: the `v0.5.8` GitHub Standard Preview, platform receipts and
Actions run. Verification checks immutable status, tag source, complete public
assets/digests, updater metadata and release attestation.
